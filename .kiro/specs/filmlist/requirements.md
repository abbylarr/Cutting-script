# Requirements Document

## Introduction

Сервис "filmlist" предназначен для автоматического создания монтажных листов из видеофайлов в соответствии с требованиями Госфильмфонда РФ. Система должна обрабатывать видео через комплексный пайплайн: анализ сцен, транскрипцию аудио, диаризацию спикеров, визуальный анализ кадров и формирование итогового документа в формате DOCX. Пользователи могут загружать видео с автоматической транскрипцией или предоставлять готовые SRT файлы.

## Requirements

### Requirement 1

**User Story:** Как продюсер или специалист по монтажу, я хочу загрузить видеофайл и получить автоматически созданный монтажный лист, чтобы сэкономить время на ручном создании документации.

#### Acceptance Criteria

1. WHEN пользователь загружает видеофайл THEN система SHALL принять файл и создать задачу обработки с уникальным task_id
2. WHEN пользователь выбирает режим автотранскрипции THEN система SHALL выполнить полный пайплайн обработки включая извлечение аудио и транскрипцию
3. WHEN пользователь выбирает режим с SRT файлом THEN система SHALL использовать предоставленный текст и определить только наличие музыки в сценах
4. WHEN обработка завершена THEN система SHALL предоставить таблицу с колонками: № | Тайм-код начала | Тайм-код конца | Тип | Описание | Текст/Диалоги

### Requirement 2

**User Story:** Как пользователь системы, я хочу отслеживать прогресс обработки видео в реальном времени, чтобы понимать текущий статус и примерное время завершения.

#### Acceptance Criteria

1. WHEN обработка видео запущена THEN система SHALL показать анимированный процесс с описанием текущего этапа
2. WHEN система выполняет этап обработки THEN интерфейс SHALL отображать забавный текст описания процесса и примерное время завершения
3. WHEN пользователь закрывает браузер THEN обработка SHALL продолжаться в облаке без прерывания
4. WHEN обработка завершена THEN пользователь SHALL получить уведомление о готовности результата

### Requirement 3

**User Story:** Как редактор, я хочу просматривать и редактировать созданный монтажный лист с возможностью воспроизведения соответствующих моментов видео, чтобы проверить точность автоматической обработки.

#### Acceptance Criteria

1. WHEN пользователь нажимает на строку таблицы THEN видеоплеер SHALL перейти к соответствующему моменту времени
2. WHEN пользователь изменяет тип плана THEN система SHALL предоставить цветные теги для выбора (Дальний, Общий, Средний, Крупный, Деталь)
3. WHEN пользователь нажимает на тег спикера THEN система SHALL позволить переименовать спикера или выбрать из существующих
4. WHEN пользователь вносит изменения THEN система SHALL сохранить изменения и обновить DOCX файл

### Requirement 4

**User Story:** Как пользователь, я хочу управлять информацией о фильме и своими проектами, чтобы организовать работу с множественными видео.

#### Acceptance Criteria

1. WHEN пользователь создает проект THEN система SHALL позволить добавить метаданные фильма (производитель, год, страна, авторы сценария, правообладатели, продолжительность, количество серий, формат, цвет, носитель, языки)
2. WHEN пользователь открывает интерфейс THEN сайдбар SHALL отображать все проекты пользователя
3. WHEN пользователь просматривает аккаунт THEN система SHALL показать текущий баланс и доступные минуты обработки
4. WHEN пользователь пополняет баланс THEN система SHALL принять платеж через СБП по тарифу 75 рублей за минуту

### Requirement 5

**User Story:** Как система, я должна обрабатывать видео через технический пайплайн с высокой точностью, чтобы создать качественный монтажный лист.

#### Acceptance Criteria

1. WHEN система получает видео THEN она SHALL проверить формат и целостность файла
2. WHEN система извлекает аудио THEN она SHALL использовать ffmpeg для конвертации
3. WHEN система детектирует сцены THEN она SHALL использовать python-scenedetect с ограничениями на короткие сцены для избежания ложных срабатываний
4. WHEN система выполняет транскрипцию THEN она SHALL использовать OpenAI Whisper с настройками для русского языка и verbose_json
5. WHEN система обрабатывает текст THEN она SHALL использовать GPT-5-mini для экономной постобработки грамматических ошибок
6. IF доступен HF_TOKEN THEN система SHALL выполнить диаризацию через pyannote.audio
7. WHEN система распределяет реплики по сценам THEN она SHALL сохранять целостность предложений и использовать многоточия при переносах
8. WHEN система извлекает ключевые кадры THEN она SHALL брать кадры на 35% и 70% от длительности сцены
9. WHEN система анализирует кадры THEN она SHALL использовать GPT-5-mini для визуального анализа с ответом в формате JSON согласно специальному промту для режиссера монтажа
10. WHEN система создает таймкоды THEN она SHALL определить частоту кадров, конвертировать секунды в правильный формат и обеспечить непрерывность с интервалом в один кадр между сценами
11. WHEN пользователь настраивает проект THEN система SHALL предоставить выбор стартовой точки таймкода (01:00:00:00 или 00:00:00:00) и стандарта (ГФФ или Красногорский)

### Requirement 6

**User Story:** Как система, я должна обеспечивать надежность работы и обработку ошибок, чтобы гарантировать стабильную работу сервиса.

#### Acceptance Criteria

1. WHEN система сталкивается с rate limit THEN она SHALL применить exponential backoff и парсить сообщения "try again in ..."
2. IF OpenAI API недоступен THEN система SHALL использовать fallback на тестовые транскрипции
3. WHEN происходит ошибка обработки THEN система SHALL логировать детали ошибки и уведомить пользователя
4. WHEN система запускается THEN она SHALL проверить наличие обязательных переменных окружения (OPENAI_API_KEY)

### Requirement 7

**User Story:** Как разработчик, я хочу иметь четкое API для интеграции с фронтендом, чтобы обеспечить эффективное взаимодействие между компонентами системы.

#### Acceptance Criteria

1. WHEN клиент отправляет POST /upload THEN API SHALL вернуть task_id для отслеживания
2. WHEN клиент запрашивает GET /status/{task_id} THEN API SHALL вернуть текущий статус, строки результата или ошибку
3. WHEN клиент отправляет PATCH /montage/{task_id} THEN API SHALL обновить строки и регенерировать DOCX
4. WHEN клиент отправляет POST /upload_srt/{task_id} THEN API SHALL пересчитать строки на основе SRT и обновить DOCX
5. WHEN клиент запрашивает GET /download/{task_id} THEN API SHALL вернуть готовый DOCX файл
6. WHEN клиент отправляет POST /save/{task_id} THEN API SHALL сохранить изменения и регенерировать DOCX

### Requirement 8

**User Story:** Как пользователь системы, я хочу настраивать параметры таймкодов и стандарты, чтобы соответствовать требованиям конкретного архива или производства.

#### Acceptance Criteria

1. WHEN пользователь создает проект THEN система SHALL предоставить выбор стартовой точки таймкода: 01:00:00:00 или 00:00:00:00
2. WHEN пользователь выбирает стандарт THEN система SHALL предоставить опции "ГФФ" или "Красногорский"
3. WHEN система генерирует таймкоды THEN она SHALL обеспечить непрерывность с интервалом ровно в один кадр между окончанием одной сцены и началом следующей
4. WHEN система форматирует таймкоды THEN она SHALL использовать выбранные пользователем настройки для всего проекта

### Requirement 9

**User Story:** Как администратор системы, я хочу иметь возможность настройки и тестирования системы, чтобы обеспечить корректную работу в различных условиях.

#### Acceptance Criteria

1. WHEN система настраивается THEN она SHALL использовать .env файл с OPENAI_API_KEY (обязательно) и HF_TOKEN (опционально)
2. WHEN система тестируется THEN должны быть покрыты сценарии с/без SRT, длинные/короткие сцены, наличие музыки, недоступность OpenAI
3. WHEN система документируется THEN должен быть README с инструкциями по установке и запуску, а также Swagger документация API
4. WHEN система запускается THEN предпочтительно использовать venv311 для backend
